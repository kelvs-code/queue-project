Why queues are necessary

  • They enforce fairness. No item can be skipped or overtaken; the oldest request always leaves first.
  • They absorb speed mismatches. A producer (patients arriving, a program sending print jobs) and a consumer (the doctor, the printer) work at different speeds. The queue holds the backlog so nothing is lost.
  • Both ends are fast. Adding at the rear and removing at the front each take O(1) time. A plain array that shifts items after every removal would take O(n).
  • They keep order for free. Arrival order is the data. No sorting or timestamps are needed.
  • They support other algorithms. Breadth-first search, level-order tree traversal, and task schedulers all depend on a queue.

Chosen application: the clinic queue

Problem. A clinic has eight waiting-room chairs. Patients take a ticket on arrival and are called in that order. The program must add a patient, call the next one, show who is next, and refuse new patients when the room is full.

Design. A circular queue built on an array. Two values describe it: front (index of the next patient) and count (patients waiting). The rear position is (front + count) % 8. The modulo makes the index wrap, so a removed patient's seat is reused and the array never needs to shift.

OperationWhat it doesTime
enqueue(name)Place patient at rear; fail if fullO(1)
dequeue()Remove and return the front patient; fail if emptyO(1)
peek()Read the front patient without removingO(1)
isEmpty / isFullCompare count with 0 and with capacityO(1)

Limitation. Capacity is fixed at eight. That is realistic for a waiting room, but a system with unpredictable load would use a linked list or a resizable array.
